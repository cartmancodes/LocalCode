# Linux TUI Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development for independent tasks and review. Steps use checkbox syntax.

**Goal:** Installable, responsive Linux terminal access to both Octet engines and existing workflows without HTTP.

**Architecture:** Textual owns the terminal loop. A controller owns a dedicated asyncio runtime thread and calls existing core/RPC and legacy session APIs directly. The thread keeps synchronous extension/persistence operations off the terminal loop while preserving session ordering. Semantic event delivery uses backpressure; display updates are batched.

**Tech Stack:** Python 3.11+, Textual, existing AgentSession/SessionRunner, PyInstaller directory bundle.

**Spec:** docs/superpowers/specs/2026-09-30-linux-tui-design.md

## Global Constraints

- No browser or listening HTTP server is needed.
- Keep print, JSON, RPC, and package-management commands.
- Preserve ordered semantic events, tool results, errors, and approvals.
- Existing provider limitations remain visible and documented.
- Targets are proposals, not measured claims: p95 startup <=1s, input <=50ms, event display <=100ms, cancellation dispatch <=100ms, idle CPU <=1% of one core.
- Do not modify user credentials, tracked .run state, or existing session data.
- No automatic commits of runtime state. Keep changes on feat/linux-tui in this checkout so the user's IDE sees the implementation.

## Review Focus

1. Pending concurrent approvals and quit: all waiters resolve safely and children close.
2. Output bursts and giant tool results: complete output remains accessible while visible rendering stays bounded.
3. Installed wheel/frozen app outside checkout: imports, fleet resources and worker entry work.
4. Legacy resume versus transcript display: upstream session identity and settings survive.
5. Noninteractive invocation: pipes keep RPC/print behavior and never enter terminal mode.
